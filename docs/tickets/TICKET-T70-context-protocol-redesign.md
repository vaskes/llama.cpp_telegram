## Постановка

Сейчас бот отправляет **всю историю целиком в каждом запросе**:

```python
# call_llama.py:790
req_body = {
    "model": MODEL,
    "messages": msgs,      # ← вся история подряд, каждый раз
    ...
}
```

Требуется перейти на модель, где бот отправляет **одно сообщение**, а
состояние держит движок.

## Почему это блокер

**Оператор, лично проверивший на практике:**
> «llama работает со слотами kv ХУЕВО. от слова совсем. отличается хоть на
> байт — prefill с нуля»

**И добавил два аргумента, которые важнее любых замеров:**

1. **Прод-движок будет другим** (Strata). Завязываться на то, *как именно*
   llama умеет prefix matching — идея так себе.
2. **Зависимость от поведения конкретного движка** — хрупкая архитектура.

**Моё измерение (Qwen3.8, 2026-10-20), для честности:**

```
turn   timing    n_prompt
  1   0.112s        26
  3   0.170s       106
  12   0.171s       474

req 1: 0.94s | 3010 токенов
req 2: 0.08s | 3010 токенов   ← тот же запрос повторно
```

На этой модели выходит плато ~0.17 с, то есть prefix matching работает.

**Но это не аргумент «делать ничего»**, а аргумент «**не строить на этом**».
Если архитектура работает только пока конкретный движок умеет дедуплицировать
префикс — при смене движка на Strata она развалится молча, без ошибки. Именно
это и есть хрупкость: не отказ, а тихая деградация.

**Реальный предел, измеренный:** `n_ctx = 262144` → ~250–300k токенов →
**700–900 КБ текста**. Мегабайт истории в контекст **не влезает физически**,
независимо от кэша.

### ⚠️ Что говорит проверка llama по п.4–5 (уже измерено, не трачу токены)

На живом инстансе llmhost1 (`ps aux | grep llama-server`):

```
флаги: --ctx-size --cache-type-k --cache-type-v --cache-ram --parallel
NO --cache-reuse flag
no slot flags
```

**`--slot-save-path` нет. Persistent slots нет.** Слот живёт в памяти процесса.

Значит на текущем llama: **рестарт движка = все сессии потеряны**, даже если
бот жив и знает про них.

Это **не противоречит** оптимизму «persistent chats должны быть» — но значит,
что проект **не может рассчитывать** на переживание рестарта движка и обязан
уметь пересоздать сессию из своего источника истины.

### Источник истины при рестартах

Оператор зафиксировал зависимость «рестарт бота = рестарт движка»
(обоснование — в `TICKET-T68-daily-restart.md`, там же поправка: llama
stateless между запросами при текущем протоколе).

Отсюда требование к дизайну T70:

> **SQLite — источник истины. Сессия у движка — производная величина,
> которую можно пересоздать в любой момент.**

Это снимает страх «сессия пропала»: пропала — пересоздали из SQLite. И это
же делает T67 (снос trim) обязательным: SQLite должен быть полным.

## Что надо спроектировать


### Ядро: кто владеет состоянием

| Модель | Бот шлёт | Состояние живёт | Цена |
|---|---|---|---|
| **A. Текущая** | всю историю | в SQLite у бота | O(контекста) на каждый запрос |
| **B. Сессионная** | одно сообщение + `session_id` | у движка | нужна поддержка stateful API |
| **C. Гибрид** | одно сообщение + краткая сводка | бот держит «долгое», движок — «горячее» | сложнее всего |

### Вопросы, без которых не начинать

1. **У Strata есть сессионный API?** Если нет — B отпадает, остаётся C.
2. **`session_id` на что?** Сейчас бот его **не отправляет вообще**
   (`req_body` не содержит ни `session_id`, ни `cache_prompt`). Для модели B
   это недостающий кусок.
3. **Как это соотносится с `/sub`?** Разделение по sub — фиксированное
   требование оператора. Значит `session_id` должен быть **per-sub**.
   Что делать при `/newsub`, `/delsub`, `/reset` — создавать новую сессию
   движка или сбрасывать старую?
4. **Что с холодным стартом?** Бот перезапустился, у движка сессии нет. Пересоздавать?
5. **Что с рестартом движка?** Бот жив, движок упал и перезапустился — все
   сессии потеряны. Кто восстанавливает? Из SQLite или начинать заново?
6. **Деградация.** Если движок не поддерживает сессии — бот обязан уметь
   откатиться в режим A, а не падать. Иначе смена движка = остановка бота.
7. **Наблюдаемость.** Сколько токенов в сессии? Кто её создал? Когда
   последний раз обращались?
